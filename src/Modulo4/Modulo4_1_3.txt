=== *Ferramentas para Requisições HTTP: Fetch e Axios* ===

No desenvolvimento de aplicações React Native, consumir APIs é uma prática comum para obter e enviar dados a partir de servidores remotos (NEIL, 2012). Existem duas ferramentas populares para realizar essas requisições HTTP: Fetch e Axios. Vamos explorar cada uma delas em detalhes, destacando suas características, vantagens, desvantagens e exemplos de uso.

Para auxiliar na compreensão dos conceitos relacionados à integração com de projetos React Native com APIs, considere o escopo de desenvolvimento de uma aplicação mobile que precisa acessar a API JSONPlaceholder. JSONPlaceholder é uma API online gratuita que simula um servidor REST e é amplamente usada para testes e desenvolvimento de aplicações web e mobile. Ela fornece uma maneira fácil para desenvolvedores obterem dados fictícios (fake data) para praticar a construção de aplicações que consomem APIs, testar recursos de frontend e realizar testes de integração.

=-=-= Fetch API =-=-=

A Fetch API é uma interface moderna baseada em JavaScript para fazer requisições HTTP assíncronas em navegadores (TILTON, 2022). Ela é frequentemente usada em projetos React Native para buscar dados de APIs ou enviar dados para servidores. A Fetch API é baseada em Promises, o que facilita o tratamento de operações assíncronas.

Uma Promise é um objeto que representa a eventual conclusão (ou falha) de uma operação assíncrona e seu valor resultante. Promises permitem que você organize seu código de forma que ele continue executando outras tarefas enquanto espera que uma operação assíncrona termine. Neste contexto, uma Promise pode estar em um dos seguintes estados:

*-Pending (pendente):* A operação assíncrona está em andamento.
*-Fulfilled (concluída):* A operação foi concluída com sucesso, e temos um resultado.
*-Rejected (rejeitada):* A operação falhou, e temos uma razão ou erro para explicar a falha.

Desta forma, em React, as Promises são frequentemente usadas para buscar dados de APIs ou executar outras operações que precisam ser concluídas antes de atualizar o estado de um componente.

A sintaxe da Fetch API é simples e direta, baseada em Promises. A função fetch() é usada para enviar requisições HTTP, e ela retorna uma Promise que resolve para a resposta da requisição. Veja abaixo um exemplo de uso da Fetch API:

fetch('https://jsonplaceholder.typicode.com/users')
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error('Erro na requisição:', error));

Observe neste código:
*-fetch('https://jsonplaceholder.typicode.com/users'):-
    -Fazemos uma requisição HTTP para a URL fornecida (https://jsonplaceholder.typicode.com/users) usando a função fetch. Ela retorna uma Promise que representa a requisição.

    -A Promise pode estar nos estados de "pendente" enquanto aguarda a resposta, "resolvida" se a requisição for bem-sucedida, ou "rejeitada" em caso de falha.

*.then(response => response.json()):*
    -O primeiro .then() é chamado quando a Promise retornada por fetch é resolvida, ou seja, quando a resposta da requisição HTTP é recebida.

    -O parâmetro response contém os dados da resposta, mas ainda não está no formato JSON. Para extrair os dados da resposta no formato JSON, usamos o método response.json(). Mas, response.json() também retorna uma Promise, pois a conversão para JSON é uma operação assíncrona. Essa nova Promise resolve com os dados JSON da resposta.

*.then(data => console.log(data)):*
    -O segundo .then() é chamado quando a conversão para JSON foi concluída e temos os dados disponíveis.

    -O parâmetro data contém o objeto JSON com os dados da resposta.

    -Usamos console.log(data) para imprimir os dados no console, permitindo que vejamos os resultados da requisição.

*.catch(error => console.error('Erro na requisição:', error)):*
    -O método .catch() é usado para capturar e lidar com qualquer erro que possa ocorrer durante o processo de requisição ou durante a conversão para JSON.

    -Outra alternativa é utilizar a estrutura do async/await com a Fetch API. Ela permite escrever código assíncrono de maneira mais clara e estruturada, fazendo com que ele pareça código síncrono. Quando usamos async/await, transformamos uma função em uma função assíncrona com a palavra-chave async, e usamos await para pausar a execução da função até que a Promise seja resolvida ou rejeitada.

Veja abaixo a estrutura básica para usar async/await com a Fetch API:

const fetchData = async () => {
    try {
        const response = await fetch("https://jsonplaceholder.typicode.com/users");
        if (!response.ok) {
          throw new Error(`Erro: ${response.status}`);
        }
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.error("Erro na requisição:", error);
      }
};
fetchData();

Observe neste código:

*async:* A palavra-chave async indica que a função fetchData é assíncrona e automaticamente retorna uma Promise.

*await fetch():* O uso de await pausa a execução da função até que a Promise retornada pelo fetch() seja resolvida. Isso significa que você não precisa usar .then(). Se a requisição for bem-sucedida, ela retorna a resposta.

*await response.json():* Mais uma vez usamos await para converter a resposta para JSON. Assim, o data conterá os dados da API quando essa operação for concluída.

*Bloco try/catch:* Usamos try para executar o código e catch para capturar quaisquer erros que possam ocorrer durante a execução da requisição ou ao processar os dados. Se houver um erro, o catch tratará o erro.

Veja no exemplo abaixo o uso da Fetch API sendo chamada dentro de um componente chamado App:

import React from "react";
import { View, Text, StyleSheet } from "react-native";

function App() {
      const fetchData = async () => {
        try {
          const response = await fetch(
            "https://jsonplaceholder.typicode.com/users"
          );
          if (!response.ok) {
            throw new Error(`Erro: ${response.status}`);
          }
          const data = await response.json();
          console.log(data); // Exibe os dados no console
        } catch (error) {
          console.error("Erro na requisição:", error); // Exibe erros no console
        }
      };
    
      fetchData();
    
    
      return (
        <View style={styles.container}>
          <Text style={styles.title}>Exemplo de uso da Fetch API</Text>
        </View>
      );
}
const styles = StyleSheet.create({
      container: {
        flex: 1,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "#f5f5f5",
      },
      title: {
        fontSize: 24,
        fontWeight: "bold",
      },
});
export default App;

=-=-= Axios =-=-=

O Axios é uma biblioteca baseada em Promises usada para fazer requisições HTTP de forma mais simples e poderosa em comparação com a Fetch API (TILTON, 2022). Em projetos React Native, o Axios é amplamente utilizado para se comunicar com APIs e servidores.

Antes, porém, precisamos instalar essa biblioteca Axios em nossos projetos React Native:

npm install axios

Veja abaixo um exemplo de uso da biblioteca Axios:

import axios from 'axios';
    axios.get('https://jsonplaceholder.typicode.com/users')
    .then(response => console.log(response.data))
    .catch(error => console.error('Erro na requisição:', error));

Em comparação com o exemplo visto usando Fetch API, podemos identificar:

*-Método .get():* Axios usa o método .get() diretamente para realizar requisições do tipo GET, enquanto Fetch exige que você especifique o método através das opções de parâmetro de sua função.

*-Transformação automática de JSON:* Com Axios, não precisamos chamar explicitamente response.json() para converter a resposta em JSON. Axios faz isso automaticamente e retorna os dados já formatados.

*Tratamento de erros:* O tratamento de erros continua sendo feito com o método .catch(), mas Axios fornece informações mais claras e estruturadas sobre os erros.

Outra alternativa é utilizar a estrutura do async/await com a biblioteca Axios. Vimos anteriormente que o uso de async/await torna o código mais legível e fácil de entender, especialmente em fluxos de operações assíncronas.

Veja no exemplo abaixo o uso do Axios sendo chamada no componente chamado App:

import React from "react";
import { View, Text, StyleSheet } from "react-native";
import axios from "axios";
    
function App() {
      async function fetchData() {
        try {
          const response = await axios.get(
            "https://jsonplaceholder.typicode.com/users"
          );
          console.log(response.data); // Exibe os dados no console
        } catch (error) {
          console.error("Erro na requisição:", error); // Exibe erros no console
        }
      }
    
    
      fetchData();
    
    
      return (
        <View style={styles.container}>
          <Text style={styles.title}>Exemplo de uso do Axios</Text>
        </View>
      );
}
const styles = StyleSheet.create({
      container: {
        flex: 1,
        justifyContent: "center",
        alignItems: "center",
        backgroundColor: "#f5f5f5",
      },
      title: {
        fontSize: 24,
        fontWeight: "bold",
      },
});
export default App;

Dentre as principais mudanças, observe:

*-Função assíncrona (async):* Criamos uma função chamada fetchData que é marcada como async, permitindo o uso do await dentro dela.

*-Uso de await:* A chamada para a requisição com Axios é feita usando await, o que pausa a execução até que a resposta seja recebida. Isso elimina a necessidade de encadeamento com .then().

*-Bloco try...catch:* Utilizamos um bloco try...catch para capturar e tratar possíveis erros durante a requisição, oferecendo uma abordagem para lidar com falhas.
Neste cenário, vamos utilizar a biblioteca Axios em nossos próximos exemplos desta aula.
