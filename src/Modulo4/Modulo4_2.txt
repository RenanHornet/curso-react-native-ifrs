=== Armazenamento e Renderização de dados dinâmicos === 

No desenvolvimento de aplicações mobile com React Native, um dos aspectos mais importantes é lidar com dados dinâmicos vindos de APIs (GHOSHAL, 2021; BOWMAN, 2022). Isso envolve obter dados de um servidor, armazená-los corretamente no estado da aplicação e renderizá-los de maneira eficiente e interativa para o usuário. Neste capítulo, abordaremos em detalhes como exibir dados obtidos de uma API em React e como tratar erros durante esse processo.

=-=-= Exibição de dados obtidos de uma API =-=-=

O React Native é uma biblioteca baseada em JavaScript que utiliza o conceito de estado para gerenciar e armazenar dados que mudam ao longo do tempo. O estado é essencial para lidar com dados dinâmicos, especialmente em aplicações que consomem APIs.

Neste contexto, podemos citar os seguintes hooks para lidar com dados dinâmicos:

*-useState:* utilizado para armazenar e gerenciar o estado local dentro de um componente.

*-useEffect:* utilizado para realizar efeitos colaterais, como a chamada a APIs, após a renderização inicial do componente.

Quando buscamos dados de uma API em React Native, normalmente usamos bibliotecas como Axios ou a Fetch API. O uso do hook useEffect é essencial para garantir que as chamadas à API sejam feitas após a renderização inicial do componente.

Veja abaixo um exemplo prático com Axios:

import React, { useState, useEffect } from "react";
import { View, Text, FlatList, StyleSheet } from "react-native";
import axios from "axios";
export default function App() {
      const [usuarios, setUsuarios] = useState([]);
    
    
      useEffect(() => {
        const fetchUsuarios = async () => {
          try {
            const response = await axios.get(
              "https://jsonplaceholder.typicode.com/users"
            );
            setUsuarios(response.data);
          } catch (error) {
            console.error("Erro ao buscar os usuários:", error);
          }
        };
        fetchUsuarios();
      }, []);
      return (
        <View style={styles.container}>
          <Text style={styles.title}>Lista de Usuários</Text>
          <FlatList
            data={usuarios}
            keyExtractor={(item) => item.id.toString()}
            renderItem={({ item }) => (
              <Text style={styles.item}>{item.name}</Text>
            )}
          />
        </View>
      );
}
const styles = StyleSheet.create({
      container: {
        flex: 1,
        padding: 20,
        backgroundColor: "#f5f5f5",
      },
      title: {
        fontSize: 24,
        fontWeight: "bold",
        marginBottom: 20,
        textAlign: "center",
      },
      item: {
        fontSize: 18,
        padding: 10,
        borderBottomWidth: 1,
        borderBottomColor: "#ccc",
      },
});

Observe neste código que:

    *-useState:* Utilizado para armazenar os dados da API.

    *-useEffect:* Executa a função de chamada à API apenas uma vez, logo após a renderização inicial, graças à dependência vazia ( [ ] ).

A resposta da API é salva no estado usuarios, o que automaticamente atualiza o componente e o re-renderiza.

Este código o componente FlatList para exibir uma lista de usuários recuperados de uma API. O FlatList é ideal para renderizar listas grandes de forma eficiente, pois renderiza apenas os itens visíveis na tela.

*-data:* Recebe o array usuarios, que contém os dados retornados da API.
*-keyExtractor:* Garante que cada item da lista tenha uma chave única.
*-renderItem:* Define como cada item do array será renderizado.

*OBS:* O FlatList é um componente fundamental do React Native projetado para renderizar listas de forma eficiente, especialmente quando o número de itens pode ser grande. Ele é otimizado para performance, renderizando apenas os itens visíveis na tela (renderização sob demanda), o que melhora o desempenho de aplicativos móveis.

=-=-= Tratamento de Erros ao consumir APIs =-=-=

O tratamento de erros é uma parte crucial ao trabalhar com dados dinâmicos e APIs em React Native. Mesmo que a API funcione corretamente, fatores externos, como problemas de rede ou resposta lenta do servidor, podem causar falhas. O objetivo do tratamento de erros é detectar esses problemas e informar o usuário de maneira clara e amigável.

Veja no quadro abaixo um exemplo de tratamento de erros com Axios:

import React, { useState, useEffect } from "react";
import { View, Text, FlatList, StyleSheet } from "react-native";
import axios from "axios";
    
export default function App() {
      const [usuarios, setUsuarios] = useState([]);
      const [error, setError] = useState(null);
    
    
      useEffect(() => {
        const fetchUsuarios = async () => {
          try {
            const response = await axios.get("https://jsonplaceholder.typicode.com/users");
            setUsuarios(response.data);
          } catch (error) {
            console.error("Erro ao carregar usuários:", error);
            setError("Erro ao carregar usuários.");
          }
        };
        fetchUsuarios();
      }, []);
    
    
      return (
        <View style={styles.container}>
          {error && <Text style={styles.error}>{error}</Text>}
          <FlatList
            data={usuarios}
            keyExtractor={(item) => item.id.toString()}
            renderItem={({ item }) => (
              <Text style={styles.item}>{item.name}</Text>
            )}
          />
        </View>
      );
}
    
const styles = StyleSheet.create({
      container: {
        flex: 1,
        padding: 16,
        backgroundColor: "#f5f5f5",
      },
      error: {
        color: "red",
        fontSize: 16,
        marginBottom: 10,
        textAlign: "center",
      },
      item: {
        fontSize: 18,
        padding: 10,
        borderBottomWidth: 1,
        borderBottomColor: "#ccc",
      },
});

Observe neste código:

    *-Estado de Erro:* Temos um estado error para armazenar mensagens de erro.

    *-Bloco try/catch:* O bloco try/catch é utilizado para capturar qualquer erro que ocorra durante a requisição. Se houver um erro, a mensagem "Erro ao carregar usuários." é definida no estado error. Temos a exibição do erro no console, de maneira que o erro completo é exibido quando ocorre uma falha na requisição.

    *-Renderização da Mensagem de Erro:* Verificamos se existe uma mensagem de erro (error) e, se existir, exibe essa mensagem na interface do usuário.
